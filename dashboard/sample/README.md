# Capibara · локальный HTML

Открыть `dashboard/sample/index.html` двойным щелчком. Сервер, сборка, npm, CDN и
сетевые запросы не нужны. Встроены **24 синтетических учебных заказа**, не Olist
и не контрольные ответы. Кнопка «Учебный набор» возвращает именно этот набор.
Его машиночитаемая копия — `sample.json`.

Три сюжета: выполнение и сервис, продажи, качество/покрытие. «Весь снимок» снимает ограничения дат, включая заказы с неизвестной датой
покупки. Период относится
к покупке, правая дата включительна. Штат — исходный штат покупателя. Столбец
месяца, штат или продавец выбирает заказы в таблице; кнопка заказа раскрывает
исходные даты, позиции и все связи отзыв–заказ. Выбор продавца означает участие
в заказе и не распределяет его GMV/оценку между продавцами. Графики доступны
клавиатурой (Tab, Enter/Space); вкладки также ArrowLeft/ArrowRight/Home/End,
диалог — Escape. Таблица листается по 12 заказов.

## Экспорт из существующей модели

Экспортёр не вызывает setup, build, reload, Docker или установку пакетов.
Нужна **уже собранная** модель с объектами из `model/40_mart.sql`.
Используется предустановленный W-07 venv с psycopg2. Задать `DATABASE_URL`
в окружении либо стандартные `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`,
`PGPASSWORD`/`.pgpass`; не сохранять реальные пароли в репозитории.

```sh
"$HOME/.local/share/rwb-hak-dev/venv/bin/python" dashboard/sample/export_data.py \
  --dataset-label 'Olist · модель, полнота ещё не проверена' \
  --output /tmp/capibara-model.json \
  --html /tmp/capibara-model.html
```

Команда читает только `core/mart` в одной `REPEATABLE READ READ ONLY`
транзакции, timeout каждого SELECT — 60 секунд. Ничего не исправляет в БД.
Прямых запросов к raw или исходным CSV нет. Все выгруженные orders/items/review
pairs сохраняются без LIMIT. Нет текста отзывов и адресов; есть идентификаторы,
штат покупателя, даты и числовые значения для drilldown. Сам HTML-экспорт
содержит эти данные; обращаться с ним как с выгрузкой модели.

Открыть исходный `index.html` → «Открыть JSON» → выбрать выгрузку. Чтение идёт
через File API, без `fetch(file://...)` и file CORS. Либо открыть сгенерированный
`/tmp/capibara-model.html`: JSON уже встроен. После смены источника фильтры
сбрасываются. Ошибочный файл оставляет текущий набор и показывает ошибку.
Ограничение импорта — 80 МиБ; это интерфейс для данного снимка, не крупная BI БД.

## Контракт и границы

`schema_version=1`, `manifest`, массивы `orders`, `items`, `reviews`, `months`.
Путь данных: 8 неизменных CSV → raw → core → mart → JSON → HTML; экспортёр
читает только последний модельный слой, raw-binding остаётся отдельной проверкой.
Проекции полей и SQL — в `export_data.py::QUERIES`. Заказы уникальны по
`order_id`, items — `(order_id,order_item_id)`, reviews — `(order_id,review_id)`.
`months` из `core.dim_date` позволяет показать пустой месяц в выбранном окне.
NULL остаётся NULL, неизвестная сумма не становится нулём. Денежные decimal
передаются строками; суммы считаются через BigInt с сохранением масштаба,
округление и преобразование для графика выполняются при отображении.
Производственные ответы следует брать из SQL/mart, не из округлённого экрана.

- Выручка: price позиций с `is_revenue=true`, без freight. При неполном покрытии
  цен или eligible заказе без items строгий итог неизвестен; известная часть
  раскрывается в формуле. Валюта BRL — предположение контекста Olist.
- GMV и чек: полный `order_gmv` из `mart.v_orders`, с доставкой, только eligible
  заказы. Среднее — сумма полных GMV / число таких заказов. Покрытие показано.
- Buyers/repeat: distinct `customer_unique_id`, все статусы выбранного окна;
  повтор = минимум два заказа в этом окне. По срезам не складывать.
- Late: два явно переключаемых варианта mart, календарный день и timestamp.
  Знаменатель — delivered с двумя датами; без дат — unknown. Недоставленные
  исключены из late denominator. Последние когорты могут быть незавершёнными.
- Review: все связи review–order с равным весом пары; sum(score)/count(score).
  Отсутствие отзыва и неизвестная оценка не равны нулю. Шкала графика 1–5;
  оценки вне диапазона сохраняются, входят в среднюю и имеют отдельный count.
- Даты без timezone не превращаются в UTC. Аномалии только помечаются.
  Delivered не доказывает выкуп; UI не устанавливает виновника/денежный ущерб.

Manifest содержит время экспорта/транзакции, метод, row counts, версии, хеши
SQL, payload и локальных контрактов. `data_sha256` считается по UTF-8 JSON
массивов без manifest, `ensure_ascii=False,separators=(',',':')`.
`checkout_head` не заменяет file hashes в dirty checkout. UI показывает manifest,
но не выполняет независимую сверку хеша или raw-binding.
`exported_not_validated` означает успешное чтение, **не** полный Olist/model PASS.

## Проверка этого результата

`checks.js` — малый DOM-сценарий для исполнения внутри HTML preview (в production
HTML не подключён). `qa-results.json` фиксирует фактически исполненные проверки.
Офлайн-проверки экспортёра: `PYTHONDONTWRITEBYTECODE=1 python3 dashboard/sample/check_export.py`.
Проверяются фильтры/выбор графика, клавиатура/диалог, пустое/неизвестное состояние,
сохранение набора при ошибке импорта и узкий экран 390 px. Никакие эти проверки
не заменяют реальный Olist model export и UI E2E на нём: этот этап pending.

Авторство: HTML/CSS/JS, экспортёр, синтетический пример и проверки созданы ИИ
(Codex / Sol, W-16). Семантика сверена с model/CONTRACT.md, 40_mart.sql,
50_answers.sql, docs/metric-definitions.md и принятым HTML override брифа.
