## Ссылочная целостность

- Позиции, платежи и отзывы без заказа — 0; позиции без товара или продавца — 0.
- Заказы без позиций — **775** (в основном unavailable/canceled). INNER JOIN к items их потеряет.
- Заказ без платежа — **1**. Заказов без отзыва — 768.
- Товары без категории — **610** (1 537 доставленных позиций). Две категории есть в товарах, но нет в справочнике перевода: `pc_gamer`, `portateis_cozinha_e_preparadores_de_alimentos`.

## Контрольные цифры: как они получаются

Все пять сошлись. Определения, которые за ними стоят:

| Вопрос | Контроль | Определение |
|---|---|---|
| 1. Выручка по месяцам | 13 221 498.11, 24 строки | `sum(price)` по позициям заказов в статусе `delivered`, месяц — по `order_purchase_timestamp`; ноябрь 2016 добавляется из календаря с нулём |
| 2. Топ продавцов | 226 987.93 | то же, на уровне позиции по `seller_id` |
| 3. Средний чек | 159.88 | `avg(sum(price + freight))` на **заказ**, delivered. Строк на заказ 1.142 |
| 4. Покупатели | 96 096 / 3,12% | `customer_unique_id` по **всем** заказам, вне зависимости от статуса |
| 5. Категории | 74, топ 1 233 131.72 | 73 категории + «пустая» как отдельный член; выручка как в вопросе 1 |

Расхождения в определениях, которые нужно зафиксировать в модели и записке:

- **Выручка без доставки, а чек с доставкой.** Нужны две явные метрики, например `item_revenue = price` и `order_gmv = price + freight`.
- **Выручка считается только по delivered, а покупатели — по всем заказам.** Если покупателей считать только по доставленным, выйдет 93 358 и 3,00%. Признак «заказ даёт выручку» должен быть один на всю модель.
