обёртки и прежний `<AnswersB />` передан ей как `fallback`. Маршруты и навигация

При готовом полном контракте в этом же слоте отображается сравнение вариантов.
При HTTP 500/503 или нарушении полного контракта показана ошибка и повтор:
не производится переход к сокращённому ответу, скрывающий сбой.

Tradeoff: сохраняются две реализации представления в исходниках для перехода,
но одновременно монтируется одна. Старый endpoint опускает
`units_with_unknown_price`, `duration_denominator`, известную часть суммы,
покрытие частей, часть Q10 coverage. Эти значения нельзя восстановить локально,
поэтому UI не придумывает их и ждёт полный endpoint от независимого API-агента.
Прежний URL выбора A/B сохранён. В полном представлении старые параметры
`q6/q7/q7b/q9/q10/q10p/q10b` не отфильтровывают сравнение: все варианты видны.
CSV-экспорт сохранён; выгружаются исходные поля вариантов и знаменатели,
отдельно таблицы Q9 и coverage Q10. CSV NULL — пустая ячейка; ноль — `0`.

## Дизайн перед реализацией

Существующие токены: фон `#f4f5f7`, поверхность `#ffffff`, текст `#1b1f24`,
граница `#e3e6ea`, акцент `#2f7fb8`, второе сравнение `#b8875a`. Шрифт приложения
IBM Plex Sans / Segoe UI, табличные цифры; ID товара — существующий mono.
Блок наследует эти переменные, не меняет бренд и соседние разделы.

Слева направо: название вопроса → конкретный охват → сравнение → точные строки.
Q6 показывает отдельных лидеров двух популяций и точки дата × цена без
соединения/усреднения разных цен одного дня. Q7 сравнивает оба определения
опоздания внутри каждой популяции. Q8 — распределение статусов с полосами.
Q9 — штаты отдельно от способов оплаты; два периода стоят рядом. Q10 —
два правила оценок в сравнительных графиках, затем все варианты в точных
таблицах и отдельный охват. Все элементы выровнены по левому краю, числа вправо.

Проверка плана по brief: новая hero/KPI-сетка, декоративные плашки и технические
селекторы не нужны. Сохраняются панели приложения; сравнительные графики —
часть вопроса, а не новый режим. Подписи объясняют только популяцию,
знаменатели, неизвестные значения и ограничения сложения.

## Что готово

- Один слот блока Б в сохранённом переключателе A/B. Q1–Q5 не изменены.
- Q6: обе популяции, каждый лидер с равным максимумом, отдельные точки
  дата × цена, NULL даты/цены в таблице; повторяемый unknown-price итог товара
  показывается один раз на товар и не суммируется по истории.
- Q7: порог `orders_count >= 500` из задания, оба определения опоздания,
  обе популяции, отдельные знаменатели срока и опозданий.
- Q8: текущие статусы, доли, позиции; без обещания переходов или конверсии.
- Q9: таблица штатов 2018 и две отдельные таблицы способов оплаты. Известная
  часть суммы и охват показаны рядом с неизвестным итогом; среднее число частей
  отдельно по всем типам и кредитной карте. Периоды не суммируются.
- Q10: пять оценок для каждого из восьми именованных вариантов, сравнение
  четырёх серий внутри популяции, разрывы вместо NULL на графике, отдельная
  таблица всех coverage-полей. Пересекающиеся причины/оценки не складываются.
- Успешный пустой ответ, неизвестное значение, ожидание и отказ различаются.
  Ошибка имеет кнопку повтора; уход со страницы отменяет запрос.

Adapter — `app/web/src/block-b/contract.ts`: согласованная форма
`q6.rows/q7.rows/q8.rows/q9.states/q9.methods/q10.rows/q10.coverage/meta.scope`.
PostgreSQL numeric/bigint strings нормализуются, NULL сохраняется; пустая строка,
неизвестный enum, потерянное поле, повтор ключа, неполная сетка Q10 или coverage
дают ошибку контракта. `meta` сохраняется целиком и доступно в раскрытии.
Дополнительного HTTP adapter, SQL или API-изменения в этой порции нет.
