# Заметки докладчика

## 1. Проверка данных и сборки core — замена слайда 10

Независимый CSV oracle использовал восемь файлов и Decimal: считал строки, поля, ключи, ссылки, суммы и выбранные метрики. Восемь Git blob hashes совпали с ранее сохранённым source-tree evidence; это не привязка live raw к этим CSV. На PostgreSQL 16 прошёл synthetic lifecycle: build, rebuild, сравнение fingerprints содержимого и DDL, late failure с откатом, raw до и после, answers и check. Свежий интегрированный прогон: 182 шага, не 182 независимые бизнес-проверки. Десять синтетических заказов для lifecycle, 16 — для Q6–Q10.

Полный Olist DB и CSV/raw equality не запускались: connection refused, Docker unavailable, guard 78. План: установить происхождение raw, затем на разрешённом окружении выполнить полный lifecycle и сравнить core/mart с oracle. Старые 129 секунд и 42/42 из исходного PPTX — исторические цифры другого отчёта. Сборка не заявлена полностью проверенной или развёрнутой.

## 2. Данные: влияние и обработка — appendix рядом со слайдами 8/9

99 441 customer_id относится к заказам, 96 096 customer_unique_id — к покупателям. У 250 ID несколько ZIP-префиксов, это не доказательство переезда. 99 224 пары отзыв–заказ, 98 410 review_id, 789 ID связаны с несколькими заказами, у 547 заказов несколько строк. Оба случая — наблюдаемый grain, а не ошибка данных. Для оценки необходимо выбрать вес: связь, отзыв или заказ.

Пропуски дочерних записей могут быть состоянием выгрузки; причины неизвестны. Две категории без перевода — pc_gamer и portateis_cozinha_e_preparadores_de_alimentos. Одобрение заказа order_approved_at не означает дату денежного поступления. Причины нарушений дат неизвестны; 166 и 23 не складывать без проверки пересечения. Правила обработки — рекомендации; этот пакет не доказывает полную реализацию каждого правила в текущем core.

## 3. Проверки ошибок — дополнение к слайду 14

Денежная delta = сумма payment_value минус сумма price + freight_value, агрегированных отдельно по заказу. Все статусы, 98 665 заказов с обеими сторонами. Точная ненулевая delta: 639 заказов, −1 819,51. Строго больше 0,01 по модулю: 366, −1 818,84. Не смешивать пары. Причина расхождений не установлена; метод старого профиля неизвестен.

Для той же популяции соединение строк позиций и платежей даёт 117 601 строку, 275 заказов имеют несколько строк с обеих сторон. Это расчёт кардинальности по CSV, а не выполненный SQL. Две намеренные мутации проверяют включительность порога и знаменатель опозданий, но не все возможные ошибки. Формулу «каждый вывод проверяли вторым независимым способом» из PPTX следует убрать. Также не утверждать, что данные устанавливают виновника задержки или что PostgreSQL гарантированно подходит до 5 млн строк.
