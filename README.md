# Capibara: модель данных Olist

[Комплект для команды и жюри](docs/submission/index.html) · [Передача и порядок демо](docs/submission/FINAL-HANDOFF.md)

Решение кейса RWB использует восемь CSV Olist. `raw` сохраняется; ответы строятся из `core` и `mart`. Реализованы сборка, SQL и определения для всех десяти опубликованных вопросов, а также история категорий. Состав сдачи и границы проверок собраны в единой точке входа выше.

Полный запуск текущей модели на Olist и результаты Q6–Q10 из неё ещё не выполнены. На малых синтетических данных PostgreSQL 16.15 прошли 182 проверки с привязкой к хешам кода: [протокол](docs/phase-20261028/evidence/release-final-pg16/summary.json). Ранее опубликованная [полная выгрузка Q1–Q5](research/implementation-review-20261028/full-model-answers.json) относится к другой версии модели; это не подтверждение текущего полного lifecycle.

Для автономного показа доступны [полный дашборд предыдущей выгрузки](dashboard/index.html) с соседним `data.js` и [отдельный HTML на 1 000 реальных заказов](dashboard/olist.html). Происхождение и ограничения — в [передаче](docs/submission/FINAL-HANDOFF.md).


## Ответы Q1–Q10 и проверка

Q1–Q5 ниже подтверждены независимым CSV-расчётом и ранее опубликованной выгрузкой mart коллеги. Q6–Q10 — численный контрольный профиль независимых CSV-расчётов; **это ещё не результаты полного запуска текущего core**. SQL всех десяти вопросов реализован. Определения альтернатив сохранены, их нельзя смешивать в один итог.

Группы `within_score` могут пересекаться: складывать counts как уникальных покупателей/заказов нельзя. Альтернатива `single_score_only` исключает 189 delivered-заказов с разными оценками. Доли используют число известных сравнений дат, средние — число известных неотрицательных сроков.
