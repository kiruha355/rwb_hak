# Чат с данными: вопросы на естественном языке (text-to-SQL)

**Статус:** 💡 идея · **Дата:** 2026-10-28 · **Приоритет:** часть стратегии; прототип — бонус

## Зачем
Самое перспективное направление self-service: человек пишет «сколько мы заработали
в мае на электронике?», LLM переводит вопрос в SQL поверх модели и отвечает цифрой
с пояснением.

Именно здесь чистая модель критична: LLM отвечает правильно, только если таблицы
понятные, а бизнес-правила зашиты в модель (`is_revenue`, зерно в комментариях,
готовые поля). На `raw` она будет ошибаться так же, как люди: суммировать доставку
в выручку, считать покупателей по `customer_id`, терять пустые категории.

Сильный аргумент на защите: **наша модель делает LLM точнее.** Можно показать один и
тот же вопрос на `raw` и на `core`/`mart` и сравнить ответы с контрольными цифрами.

## Суть
```
вопрос пользователя
   │
   ▼
LLM + catalog.json (таблицы, зерно, ключи, описания метрик) — без строк данных
   │
   ▼
SQL только к mart/core, только SELECT, роль read-only, лимит времени
   │
   ▼
ответ: цифра + какой SQL выполнен + какие метрики и правила использованы
```

## Правила безопасности и качества
- Роль базы только на чтение, только схемы `core`/`mart`.
- Всегда показывать SQL и определение метрики, чтобы ответ можно было проверить.
- Если метрика есть в семантическом слое — использовать её определение, а не сочинять формулу.
- Набор контрольных вопросов (блок А + Б) как тест-кейс: ответ LLM сравнивается с эталоном.
